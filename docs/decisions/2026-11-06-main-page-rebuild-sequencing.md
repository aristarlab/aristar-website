# 결정: 메인 페이지 재구성의 구현 시점 분리

- 일자: 2026-11-06
- 결정자: CEO
- 상태: 확정
- 주관: IT본부 (구현), 전략기획본부 (명세)
- 선행 결정: [웹사이트 스택과 메일 분류 기반](2026-11-06-web-stack-and-mail-platform.md)

## 배경

CEO 지시로 해외 유명 웹사이트 UI/UX를 참고해 메인 페이지를 재구성한다. 벤치마킹 명세(`docs/plans/2026-11-06-design-bench-main-page.md`)가 작성되고 IT본부장 검토를 통과했다.

명세의 최우선 2개 항목이 선행 조건에 걸렸다.

- **결함 1** — 제품 타일에 링크가 0개. `/<슬러그>` 서비스 소개 페이지로 연결해야 한다.
- **결함 2** — 문의 메일에 사업 태그가 없어 VOC 자동 분류(`taxonomy.yml` 1순위 규칙)가 작동하지 않는다. 태그 부착은 서비스 페이지 CTA 책임이다.

두 항목 모두 `/esay-memory-eng` 같은 서비스 페이지가 실존해야 성립한다. 그런데 서비스 페이지 규격(`.claude/rules/frontend/service-pages.md`)의 적용 경로는 `app/(services)/**`로 Next.js App Router 전용이고, 현재 GitHub Pages 정적 사이트에는 대응 산출물이 없다.

## 선택지와 결정

| 선택지 | 장점 | 단점 |
|---|---|---|
| **Next.js 전환과 묶어 처리 (결정)** | 이중 작업이 없다. 서비스 페이지를 한 번만 만든다 | VOC 사업별 자동 분류 가동이 전환 완료까지 늦어진다 |
| 정적 임시 페이지를 지금 만들기 | 메일 자동 분류를 즉시 시작할 수 있다 | 정적 HTML로 3개 페이지를 만든 뒤 Next.js 전환 시 같은 페이지를 다시 만들어야 한다 |
| 전면 보류 | 없음 | 지금 적용해도 이중 작업이 없는 CSS 개선까지 함께 지연된다 |

**결정: Next.js 전환과 묶어 처리한다.**

## 구현 그룹 분리

IT본부장 제안에 따라 명세 5절 우선순위를 전환 일정 기준으로 재배열한다.

### 그룹 A — 지금 정적 사이트에 적용 (이중 작업 위험 낮음)

순수 CSS·마크업 변경이라 Next.js 이식 시 그대로 옮겨진다.

- 다크 타일 폐기 + 토큰 통일 + 중립 배지 (명세 5절 3위)
- 360px 브레이크포인트 추가 (5위)
- `h1` 자간 `clamp()` 보정 (6위)
- 카드 그리드 3단 명시 (7위)
- 섹션 경계 리듬 확인 (8위)
- 스크롤 단계적 공개 (9위) — `prefers-reduced-motion` 강제 해제 구현이 포함될 때만. caniuse 재확인 전까지 보류

### 그룹 B — Next.js 전환 후

- 제품 타일 "자세히 보기" 링크 (1위)
- 서비스 페이지 CTA 사업 태그 (2위)
- 추상 제품 다이어그램 교체 (4위) — 링크가 들어갈 타일과 함께 작업하는 것이 자연스러움

## 영향

- **VOC 사업별 자동 분류는 전환 완료 시점까지 가동되지 않는다.** 그 기간 메인 페이지 공용 문의는 `사업/미분류 + 상태/신규`로 적재되고 고객지원팀이 사람 손으로 확인한다. 이는 `mail-ops.md` 분류 순서 4단계에 따른 정상 동작이며 추측 배정을 하지 않는다는 원칙과 일치한다.
- 그룹 A는 운영 중인 `index.html`을 직접 수정한다. 별도 구현 지시와 검수를 거친다.
- 명세는 구현 지시가 아니다. 그룹 A 착수에도 CEO 승인이 별도로 필요하다.
