# 메인 페이지 해외 레퍼런스 UI/UX 벤치마킹

- 일자: 2026-11-06
- 지시자: CEO (`/design-bench 메인 페이지`)
- 주관: 전략기획본부(브랜드팀) · 조사: 리서치팀 3개 · 구현 검토: IT본부장
- 결론: 명세 확정(320줄). IT본부장 검수 조건부 통과 → 지적 6건 반영 완료. 구현은 CEO 결정에 따라 2개 그룹으로 분리.

## 한 것

### 1. 현황 파악에서 구조적 결함 5건 발견

디자인 문제가 아닌 것이 2건 섞여 있었다.

| # | 결함 | 성격 |
|---|---|---|
| 1 | 제품 타일에 `<a>` 태그 0개 | `/<슬러그>` 소개 페이지 계획과 단절 |
| 2 | 문의 `mailto`에 사업 태그 없음 | VOC 자동 분류 1순위 규칙이 작동 불가 |
| 3 | 추상 제품 2개가 `aria-hidden` 장식 SVG만 | 설명 기능 부재 |
| 4 | 브레이크포인트 1개(768px) | 360px 대응 없음 |
| 5 | 토큰 밖 하드코딩 색 14개 | CSS 5개 + SVG `fill`/`stroke` 속성 9개 |

### 2. 리서치 5축 조사 (리서치팀 3개 동시 진행)

Apple(쇼케이스) · Vercel(배지·그리드) · Stripe(다이어그램) · Notion(가독성) · Linear(톤) + 한국어 조판.

**레퍼런스로 답이 안 나온 것을 답이 안 난다고 보고한 것이 이번 조사의 성과다.**

- "성숙도가 다른 제품을 나란히 두는 위계 장치" → Apple에 사례 없음(판매 가능 제품만 게시). 자체 설계 영역으로 분류.
- "Linear의 라이트 베이스 + 다크 강조 블록" → **전제 오류.** Linear 마케팅 사이트는 전체가 다크 캔버스. 해당 축 폐기.
- Linear의 "빠른 체감 속도" → 제품 앱의 local-first 아키텍처 문제이지 마케팅 사이트 기법이 아님. 떠도는 전환 시간 수치는 전부 비공식 역추출. `prefers-reduced-motion`·포커스는 Linear 대신 WCAG 2.3.3 / 2.4.7을 직접 근거로 전환.
- 한글 줄 길이 "29~32자 / 120자" → 원 출처 URL이 다른 도메인으로 리다이렉트되고 병기된 출처는 해당 숫자를 언급조차 하지 않음. **판단 불가로 처리하고 근거로 쓰지 않음.**
- Vercel 배지 구체 수치 → 비공개(1차 미확인). 우리 토큰으로 직접 정의.

### 3. 한국어 조판 9개 쟁점 판정

| 쟁점 | 판정 |
|---|---|
| `h1` 자간 `-0.04em` | **조정.** px 기준 `clamp()`로 재정의 |
| 본문 `line-height: 1.5` | **유지.** 바꿀 근거 없음 |
| `keep-all` + `break-word` | **유지.** MDN 권장과 일치 |
| `ch` 단위 본문 폭 설계 | **금지.** 한글 전각과 불일치 |
| `text-wrap: balance`/`pretty` | **도입 안 함.** 수동 `<br>` 유지 |
| 한글 줄 길이 권장치 | **출처 미확인 처리** |

행간 유지 근거: W3C klreq의 160%는 설명용 예시이고 권장치가 아니다. WCAG 1.4.12의 150%는 "사용자가 1.5배로 늘려도 깨지지 않아야 한다"는 접근성 하한 요구사항이지 적정 디자인값이 아니다. 리서치팀 2곳 판정 일치.

### 4. 자체 설계 — 성숙도 위계

- **다크 타일 폐기.** 콘텐츠 자동화만 다크였던 것이 "성숙도"가 아니라 "중요도"로 읽히는 의도하지 않은 위계를 만들고 있었다. 폐기로 결함 5의 하드코딩 색도 동시 해소.
- **배지는 3개 사업 전부 동일한 중립 스타일**(테두리 `--line`, 텍스트 `--muted`, 투명 배경, 999px pill). 구분은 레이블 텍스트로만. 필터형/윤곽형 2단계 대안은 어느 쪽에 강조를 줘도 위계가 재생산되므로 기각.
- **신규 색 토큰 0개.** 기존 토큰만으로 구현되어 브랜드팀 승인 절차 자체가 불필요해졌다.

### 5. IT본부장 검수 — 조건부 통과, 지적 6건 전부 반영

| # | 지적 | 조치 |
|---|---|---|
| 1 | `role="img"`이 하위 `<text>`를 접근성 트리에서 평탄화 → 스크린리더가 단계 시퀀스를 못 읽음 | SVG는 장식 유지, 단계 목록을 실제 HTML `<ol><li>`로 병치하는 (b) 방식 채택 |
| 2 | `prefers-reduced-motion`을 실제로 끄는 구현 누락 | `@media` 블록에서 `animation:none`/`opacity:1`/`transform:none` 강제 명시 |
| 3 | 7절이 가리키는 Lighthouse 과제가 8절에 없음 | 8절 10번으로 추가 |
| 4 | `taxonomy.yml` "3순위" 인용이 유형 축을 가리킴 | `mail-ops.md` 분류 순서 4단계로 정정 |
| 5 | `service-pages.md`의 `mailto` 포맷이 구버전(인코딩 없음) | **비서실장이 규칙 파일 직접 수정** (RFC 3986 근거 명기) |
| 6 | "자세히 보기" 링크 배치 위치 미지정 | 세 타일 공통 "desc 다음, 시각 자료 앞"으로 통일 |

실측 과제는 9건 → 12건으로 확대(Lighthouse, 낭독 순서 검증, reduced-motion 실동작, 탭 타겟 44×44px).

## 검증 결과

| 항목 | 결과 |
|---|---|
| 브랜드팀 대비비 수동 계산(4.65:1 / 5.07:1) | WCAG 상대휘도 공식으로 재계산 → 4.66:1 / 5.07:1 **일치** |
| `h1` 자간 보간식 앵커 | 재계산 → -0.851px / -1.750px, 목표값 **일치**. `clamp` 동작 정상 |
| SVG 하드코딩 색 개수 | 브랜드팀 지적대로 9개 추가 확인. **비서실장 최초 집계(5개)가 불완전** |
| `--subtle`(#86868b) on white | 3.62:1 — AA 본문 미달이나 `.about h2 span`(30~52px, w700) 한 곳에만 사용 → 큰 텍스트 기준 3:1 **통과. 위반 아님** |
| IT본부장 지적 6건 file:line | 전부 교차 확인 **타당** |
| 브랜드팀 수정 5건 반영 | 파일에서 전부 확인 |

### 명세에 없던 사실 2건 (비서실장 검증에서 발견, 반영 완료)

1. **제안 자간이 Toss보다 오히려 느슨하다.** em 환산 -0.0236em ~ -0.0190em으로 Toss 최대치(-0.025em)의 0.76~0.94배. 원 지적("1.4~1.6배 과함")을 해소하면서 기준선보다 여유 있는 쪽에 착지. 안전한 방향이라 값 유지, 근거만 기록.
2. **본문 폭 환산의 전제가 어긋났다.** 본문 17px 가정이나 `body`에 `font-size` 선언이 없어 실제 16px. 재환산하면 425~595px → 382~561px. 적용 대상이 19~26px로 개별 지정돼 있어 `body`가 직접 기준이 아니므로 수치 대신 **전제 어긋남을 표기**.

## 안 한 것과 이유

- **구현** — 이번 과제는 벤치마킹 명세다. 구현은 CEO 승인 후 별도 착수한다. `index.html`을 수정하지 않았다.
- **실제 SVG·`<ol>` 제작** — 노드와 흐름을 말로 정의만 했다. 제작은 프론트엔드팀·컨텐츠본부 작업이다.
- **`view-timeline` 도입 확정** — `animation-timeline: view()`의 Baseline 진입 시점이 출처 간 표기가 불일치한다(MDN 가이드의 버전 번호 vs 속성 페이지의 "Baseline 2026"). caniuse 직접 확인 전까지 보류 권고.
- **커밋** — CEO 요청 시에만 한다.
