# 시각 방향 제안 — 회사·서비스 소개 사이트

- 일자: 2026-11-06
- 지시자: CEO (`/frontend-design`)
- 성격: **제안.** 확정 명세가 아니다. `docs/plans/2026-11-06-design-bench-main-page.md`와 일부 충돌하며, 어느 쪽을 택할지는 CEO 결정 사항이다.

## 0. 대상 정의 (설계의 출발점)

- **무엇**: 서울의 소프트웨어 스튜디오 AristarLab의 회사 소개 + 3개 사업 소개 사이트
- **누구에게**: ① 앱 출시를 기다리는 일반 사용자 ② 제휴·채용 문의자 ③ Google Play 등 심사 주체
- **핵심 과업**: "이 회사가 무엇을 만드는지"를 과장 없이 알리고, 각 사업의 소개 페이지로 보낸다
- **고유 소재**: 회사가 스스로 내건 문장 — "시끄러운 일상을 위한 조용한 소프트웨어"

이 문장이 설계의 제약이다. **조용함을 주장하는 회사가 92px 헤드라인을 쓰는 것은 자기모순이다.** 현재 사이트가 그렇게 되어 있다.

## 1. 색 — 6개 값

기능명으로 부른다. 장식적 이름을 쓰지 않는다.

| 토큰 | 값 | 역할 | 대비비 (paper / white) |
|---|---|---|---|
| `--ink` | `#0F1C24` | 제목·본문 | 15.97:1 / 17.33:1 |
| `--ink-mid` | `#45575F` | 보조 텍스트·메타 | 6.96:1 / 7.55:1 |
| `--hairline` | `#94A3AB` | 선·구분자 **전용** | 2.39:1 / 2.60:1 — **텍스트 금지** |
| `--paper` | `#F4F6F6` | 면 | — (면 구분용) |
| `--page` | `#FFFFFF` | 바탕 | — |
| `--signal` | `#2E6354` | 링크·포커스·상태 | 6.39:1 / 6.93:1 |

전부 WCAG 상대휘도 공식으로 계산해 검증했다. `--hairline`은 본문 기준에 미달하므로 선과 구분자에만 쓴다.

**왜 잉크 계열인가**: 단색 명도 스케일로 위계를 만든다. 이것은 Linear 리서치에서 확인된 유일한 유효 교훈("액센트는 클릭 가능한 것에만")을 구조적으로 강제하는 방식이다 — 텍스트에 쓸 색이 애초에 없으므로 액센트가 장식으로 번질 수 없다.

**왜 액센트가 청록인가**: 잉크가 이미 청색으로 기울어 있다. 여기에 파란 액센트를 얹으면 텍스트 스케일의 일부로 읽히고 신호 기능을 잃는다. 잉크 계열 밖의 단일 색이어야 하며, 채도가 낮고 어두워 본문 대비 기준을 통과하는 값으로 `#2E6354`를 택했다. 현재의 `#0066cc`는 이 조건을 만족하지 못한다 — 잉크와 같은 색상 계열이다.

## 2. 타입 — 2종

| 역할 | 서체 | 이유 |
|---|---|---|
| 성명문·사업명 | **Gowun Batang** (고운바탕, 한글 세리프) | "조용한"을 담는 목소리. 화면용 한글 세리프는 소프트웨어 사이트에서 거의 쓰이지 않는다 |
| 본문·UI·메타 | **IBM Plex Sans KR** | "소프트웨어"를 담는 목소리. 엔지니어링 맥락을 위해 설계된 서체이고 한글 커버리지가 있다 |

두 서체 모두 Google Fonts에서 HTTP 200으로 제공을 확인했다.

**Noto Sans KR을 쓰지 않는 이유**: 한글 웹의 기본값이다. 어느 프로젝트에나 손이 가는 선택이며, 그 자체로는 아무 입장도 표명하지 않는다. 서체 두 종이 회사의 두 축(조용함 / 소프트웨어)을 그대로 담는 편이 이 브리프에 고유하다.

### 타입 스케일

| 요소 | 크기 | 행간 | 자간 |
|---|---|---|---|
| 성명문 | 36px → 44px | 1.45 | -0.01em |
| 사업명 | 24px | 1.3 | 0 |
| 본문 | 17px | 1.6 | 0 |
| 메타·상태 | 14px | 1.5 | 0 |

**자간을 0으로 두는 근거**: 리서치에서 확인된 Pretendard 공개 가이드가 중간 이하 제목에 0px을 권한다. 최대 44px까지만 쓰는 스케일에서는 음수 자간이 필요한 구간이 없다. **부수 효과로 승인된 명세의 `clamp()` 자간 보간식 전체가 불필요해진다.**

**행간 1.6은 근거가 아니라 설계 선택이다.** 한글 전용 행간 수치를 제시하는 1차 자료는 없다는 판정(리서치팀 2곳 일치)을 유지한다. 1.5에서 1.6으로 두는 것은 17px 본문·540px 측정폭 조합에서의 판단이며, 증거로 주장하지 않는다.

**본문 측정폭 540px**: 전단짜기 "활자틀 너비 25~35배" 기준의 17px 환산(425~595px)과 16px 환산(382~561px) 양쪽에 모두 들어간다.

## 3. 레이아웃 — 매단 들여쓰기 색인

카드 그리드를 쓰지 않는다. 세 사업을 동일 구조의 행으로 세워 **성숙도가 중요도로 읽히는 것을 구조적으로 차단**한다(승인된 명세의 요구사항).

├─────────────────────────────────────────────────────┤
│                                                     │
│                                                     │
│     시끄러운 일상을 위한                              │  ← 36~44px 세리프
│     조용한 소프트웨어                                 │     여백이 무게를 든다
│                                                     │

│         │                                           │
├─────────┼───────────────────────────────────────────┤
│         │                                           │
│ 사내     │  콘텐츠 자동화                              │

- **정렬**: 전부 왼쪽. 한글 본문에서 가운데 정렬은 읽는 시작점을 매 줄 다시 찾게 만든다. 현재 사이트는 거의 모든 섹션이 가운데 정렬이다.
- **상태 표기**: 별도 eyebrow 행이 아니라 **좌측 열**에 둔다. 열이라는 구조 자체가 "이것은 메타정보"라고 말하므로 라벨 장식이 필요 없다.
- **번호**: 사업 3개에는 **번호를 붙이지 않는다**(순서가 아니다). 파이프라인 단계에만 붙인다(실제 순서다).
- **라운드**: 상호작용 표면에만 쓴다. 라운드값이 "누를 수 있음"을 뜻하게 한다. 모든 요소에 같은 값을 돌리지 않는다.

## 4. 원칙

1. **대담함은 한 곳에만.** 이 사이트의 모험은 "거의 빈 첫 화면"이다. 조용함을 주장하는 회사의 가장 정직한 선택이다. 나머지는 전부 조용하게 둔다.
2. **비트리거 모션 없음.** 스크롤 등장 효과를 쓰지 않는다. 사용자 동작에 답하는 전환만 둔다.
3. **구조가 정보다.** 선·열·번호는 내용의 성질을 표현할 때만 쓴다.
4. **없는 것은 그리지 않는다.** 가격표·고객 로고·수치 대시보드·후기·실적. 레퍼런스에 있어도 쓰지 않는다.
5. **품질 하한**: 360px 대응, 키보드 포커스 가시, `prefers-reduced-motion` 존중, 본문 대비 4.5:1 이상.

## 5. 자기검토 — 생성형 기본값 점검

제안을 만든 뒤 "비슷한 브리프에서도 같은 결론에 도달하는가"로 되짚었다. 네 군데를 고쳤다.

| 초안 | 문제 | 고친 결과 |
|---|---|---|
| 잉크·청자를 "한국 전통" 근거로 설명 | 문화를 의상처럼 쓰는 것. 이 회사에 고유하지 않다 | 기능명으로 토큰을 바꾸고, 청록을 택한 이유를 "잉크가 이미 청색이라 파란 액센트는 신호 기능을 잃는다"는 색 논리로 교체 |
| 헤어라인 괘선 중심의 색인 레이아웃 | 지침이 지적한 "broadsheet + 0 라운드 + 조밀한 단" 기본값에 가깝다 | 괘선 대신 **여백과 매단 들여쓰기**를 주 장치로. 조밀함의 반대인 희소함으로. 라운드는 상호작용 표면에만 |
| 섹션별 등장 애니메이션 (승인 명세 9순위) | 지침이 "생성형의 전형"으로 직접 지목. 조용한 톤과도 모순 | **삭제.** 비트리거 모션 0 |
| 사업 3개에 01/02/03 번호 | 순서가 아니다. 번호가 서열로 읽힌다 | 사업에서 번호 제거, 파이프라인 단계에만 유지 |

**삭제로 함께 사라지는 위험**: 애니메이션을 버리면 `prefers-reduced-motion` 강제 구현, `animation-timeline` caniuse 재확인, `@supports` 폴백 설계가 모두 불필요해진다. 승인된 명세의 미해결 항목 3건이 정리된다.

**남은 위험(정직하게)**: 거의 빈 첫 화면은 미완성으로 읽힐 수 있다. 완화책으로 첫 화면에 사업 3개 링크를 반드시 노출해 "회사가 무엇을 하는지"가 스크롤 없이 전달되게 했다. 그래도 이 판단은 취향의 영역이며, CEO가 보기에 빈약하면 되돌려야 한다.

## 6. 승인된 명세와의 충돌

`docs/plans/2026-11-06-design-bench-main-page.md`와 아래가 부딪힌다.

| 항목 | 승인된 명세 | 이 제안 |
|---|---|---|
| 팔레트 | `#0066cc` + Apple 계열 회색 유지 | 잉크 스케일 + `#2E6354`로 교체 |
| 서체 | Noto Sans KR 유지 | Gowun Batang + IBM Plex Sans KR로 교체 |
| 레이아웃 | 쇼케이스 타일(라운드 24px) 발전 | 카드 제거, 매단 들여쓰기 색인 |
| 자간 | px 기준 `clamp()` 보간 도입 | 스케일 축소로 자간 0, 보간식 불필요 |
| 스크롤 등장 | 9순위로 조건부 도입 | 삭제 |

### 그대로 유효한 것 (양쪽 공통)

명세의 **구조적 결함 5건 대응은 전부 살아 있다.** 시각 방향과 무관하다.

- 제품에서 `/<슬러그>` 페이지로의 링크
- 서비스 페이지 CTA의 사업 태그 (URL 인코딩 포함)
- 추상 제품을 실제 HTML `<ol>`로 설명 (접근성 평탄화 회피)
- 360px 대응
- 하드코딩 색 14개 제거
- 성숙도를 중요도로 읽히지 않게 하는 요구사항
- `keep-all` + `break-word`, `ch` 단위 금지, `text-wrap` 미도입, 수동 `<br>` 유지
