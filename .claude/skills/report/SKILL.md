# CEO 보고 및 문서화

주제: $ARGUMENTS

오늘 날짜를 먼저 확인한다: !`date +%Y-%m-%d`

## 보고 (터미널 출력)

네 블록으로 짧게 쓴다. 한국어.

1. **결론** — 한 줄
2. **한 것 / 안 한 것** — 안 한 것은 반드시 이유를 붙인다 (막혔거나, 범위 밖이거나, 승인이 필요해서)
3. **CEO 결정 필요** — 선택지와 추천안. 없으면 "없음"
4. **산출물 경로** — 파일 경로 목록

규칙: 추측·과장 금지. 검증이 실패했으면 실패했다고 쓴다. 통과한 검증만 통과했다고 쓴다.

## 보고서 파일

`docs/reports/YYYY-MM-DD-<주제>.md`

```markdown
# <주제>

- 일자 / 지시자: CEO / 주관 본부 / 협조 본부
- 결론: 한 줄

## 한 것
## 안 한 것과 이유
## 검증 결과
명령과 실제 출력 요약. 실패 포함.
## 산출물
## 다음 할 일
```

## 결정 문서 (`--decision`일 때, 또는 CEO가 선택을 내렸을 때)

`docs/decisions/YYYY-MM-DD-<주제>.md`

```markdown
# 결정: <주제>

- 일자 / 결정자: CEO / 상태: 확정
- 배경: 왜 결정이 필요했는가
- 선택지: 검토한 안과 각각의 장단점
- 결정: 무엇을 택했는가
- 근거: 왜
- 영향: 바뀌는 코드·문서·비용·일정
- 관련 문서: 링크
```

결정 문서는 나중에 수정하지 않는다. 번복 시 새 파일을 만들고 이전 문서를 링크한다.

## 반영 확인

결정이 `CLAUDE.md`의 사실(회사 정보, 사업 표, 스택)을 바꾸면 `CLAUDE.md`도 함께 갱신한다. 문서와 지침이 어긋난 상태로 두지 않는다.
