# 해외 레퍼런스 UI/UX 벤치마킹

대상: $ARGUMENTS (비어 있으면 메인 페이지 전체)

CEO 지시사항이다. 규칙은 `.claude/rules/frontend/design-reference.md`.
주관은 전략기획본부(`brand-team`), 조사는 `research-team`, 구현 명세 검토는 `it-lead`.

## 1. 현황 파악

현재 화면의 구조와 디자인 토큰을 먼저 읽는다 (`index.html` 또는 해당 라우트).
기존 디자인 언어: 여백 큰 쇼케이스 타일, 큰 타이포(`clamp`), `--accent #0066cc`, Noto Sans KR, 라운드 24px/999px.
**이 언어를 교체하는 것이 아니라 발전시킨다.**

## 2. 레퍼런스 조사 (동시 진행)

참고 축별로 `research-team`에 조사를 띄운다.

| 축 | 대표 레퍼런스 |
|---|---|
| 제품 쇼케이스 전개 | Apple |
| 추상 개념의 다이어그램 설명 | Stripe |
| 담백한 프로덕트 톤 | Linear |
| 정보 계층·가독성 | Notion |
| 카드 그리드·상태 배지 | Vercel |

조사 결과는 **패턴 설명**으로 받는다. 스크린샷·자산을 저장소에 가져오지 않는다.

## 3. 선별 (브랜드팀)

각 패턴을 4항목으로 명세한다.

1. **패턴 이름** — 무엇을 참고하는가
2. **왜 맞는가** — 조용한 톤, 3개 사업 구성, 미출시 제품 존재 상황에 맞는 근거
3. **우리 식 변형** — 기존 토큰으로 어떻게 구현하는가
4. **버린 것** — 어떤 요소를 왜 안 쓰는가

우리 제품에 없는 것(가격표, 고객 로고, 수치 대시보드, 후기)은 레퍼런스에 있어도 넣지 않는다.

## 4. 한국어 검증

영문 기준 타이포 스케일을 그대로 쓰면 한국어가 깨진다. 반드시 확인한다.
- `word-break: keep-all` 적용
- 자간을 한국어에서 과하게 좁히지 않았는지
- 긴 한국어 단어가 줄바꿈으로 터지지 않는지
- 360px 폭에서 제목이 3줄 이상 넘어가지 않는지

## 5. 산출물

`docs/plans/YYYY-MM-DD-design-bench-<대상>.md`
- 패턴별 4항목 명세
- 우선순위 (효과 대비 작업량)
- 유지할 토큰 목록
- 성능 예산: 초기 JS 150KB(gzip) 이하, LCP 2.5초 이하

## 6. 구현 이관

명세를 `frontend-team`에 넘긴다. 벤치마킹과 구현을 한 작업에서 섞지 않는다.

## 금지

타 사이트의 카피·이미지·아이콘·일러스트·폰트 파일·CSS·코드를 복제하지 않는다. 상표적 요소를 모방하지 않는다. 참고는 패턴 수준에서만.
