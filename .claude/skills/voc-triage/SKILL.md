# VOC 메일 사업별 분류

대상: $ARGUMENTS (비어 있으면 최근 7일 미처리 메일)

기준의 단일 출처는 `ops/voc/taxonomy.yml`이다. 운영 규칙은 `.claude/rules/voc/mail-ops.md`.
주관은 VOC본부(`voc-lead`)다. 분류 실행은 `support-team`에 맡긴다.

## 1. 수집

Gmail 커넥터로 support@aristar.io의 대상 메일 목록을 가져온다. 필요한 것은 **메타데이터**다: 수신시각, 제목, 발신 도메인, 현재 라벨.

## 2. 분류 (위에서부터, 먼저 맞는 것으로 확정)

1. 제목의 `[<슬러그>]` 태그 → 해당 사업 확정
2. 발신 도메인·수신 별칭 규칙 (`taxonomy.yml`의 `routes`)
3. 본문 키워드 규칙 (`taxonomy.yml`의 `keywords`)
4. 불일치 → `사업/미분류` + `상태/신규`. **추측 배정 금지.**

라벨은 `사업/*` 1개, `유형/*` 1개 이상, `상태/*` 1개를 붙인다.

## 3. 에스컬레이션

- 법무·개인정보 문구(삭제·열람 요청, 분쟁, 내용증명) → `유형/법무` + 당일 보고 + `legal-team` 이관
- 보안 신고(취약점 제보) → `security-lead` 이관
- 결제·환불 → `유형/환불`, 1 영업일 SLA

## 4. 집계

`ops/voc/reports/YYYY-WW.md`에 쓴다: 사업별 건수 / 유형 분포 / SLA 초과 건수 / 반복 이슈 상위 3건 / 제품 개선 제안 / 미분류 건수와 이유.

반복 이슈는 담당 본부로 이관하고 이관 사실을 기록한다.

## 5. 응대 초안

`ops/voc/templates/`를 써서 초안만 만든다. **발송하지 않는다.** 일정·보상·출시를 약속하지 않는다.

## 절대 지키는 것

- 메일 본문·발신자 이름·메일 주소·전화번호를 **저장소에 쓰지 않는다.** 리포트는 집계만.
- 메일 삭제·일괄 아카이브는 CEO 승인 사항. 라벨 부여는 승인 없이 가능.
- 분류 규칙을 바꾸면 서비스 페이지 CTA의 제목 태그와 일치하는지 확인한다.
