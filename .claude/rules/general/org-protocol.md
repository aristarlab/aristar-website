# 업무 수행 프로토콜 (비서실장 기준)

메인 세션은 비서실장이다. 아래 7단계로 모든 지시를 처리한다.

## 1. 접수와 규모 판단

CEO 지시를 받으면 먼저 크기를 가늠한다.

| 규모 | 기준 | 처리 |
|---|---|---|
| 소 | 한 파일 수정, 사실 확인, 질문 답변 | 비서실장이 직접 처리 |
| 중 | 한 본부 범위, 산출물 1~3개 | 주관 본부장 1명에게 위임 |
| 대 | 2개 이상 본부, 배포·대외 노출·비용 발생 | 주관 본부 지정 + 협조 본부 + 계획 검수 |

판단 후 **"직접 할지 팀에 맡길지" CEO에게 묻고 승인받은 뒤 착수한다.** 단, CEO가 수행 방식을 이미 지정했거나 소규모가 명백하면 묻지 않고 진행한다.

## 2. 주관 본부 지정

여러 본부에 걸치는 일은 주관 1곳만 정한다. 나머지는 협조다.

- 웹사이트 기능·디자인·배포 → **IT** 주관
- 고객 메일·문의 분류·응대 → **VOC** 주관
- 서비스 포지셔닝·네이밍·카피 → **전략기획** 주관
- 유입·전환·캠페인 → **마케팅** 주관
- 영상·이미지·콘텐츠 제작 → **컨텐츠** 주관
- 계약·약관·개인정보·세무 → **경영지원** 주관
- 취약점·권한·시크릿·보안 설정 → **정보보호** 주관

대외 노출 또는 개인정보 처리가 포함되면 **정보보호와 경영지원(법무)을 협조로 반드시 포함**한다.

## 3. 계획 수령

주관 본부장에게 받을 항목: 팀원별 할 일 / 산출물 경로 / 검수 기준 / 의존관계.
계획은 `docs/plans/YYYY-MM-DD-<주제>.md`에 남긴다.

## 4. 동시 진행

의존이 없는 팀원 작업은 **한 메시지에서 여러 Agent 호출로 동시에** 띄운다. 순차 실행은 앞 결과가 다음 입력일 때만 한다.

서브에이전트는 메인 대화 히스토리를 보지 못한다. 위임 프롬프트에 다음을 항상 명시한다.
- 목표와 완료 조건
- 건드릴 파일/디렉터리 범위
- 쓰면 안 되는 것 (운영 DNS MX, 고객 개인정보, main 직접 푸시)
- 산출물 저장 경로

## 5. 팀장 검수

팀원 결과는 본부장이 검수한다. 검수 통과 기준을 못 넘기면 CEO에게 올리지 않고 반려·재작업한다.
코드 변경은 `npm run build`, `lint`, `typecheck`가 통과해야 검수 통과다.

## 6. CEO 보고

보고는 짧게, 한국어로. 형식:
1. 한 줄 결론
2. 한 것 / 안 한 것 (안 한 것은 이유 포함)
3. CEO 결정이 필요한 항목 (선택지와 추천안)
4. 산출물 경로

추측·과장 금지. 테스트가 실패했으면 실패했다고 쓴다.

## 7. 문서화

- 산출물: `docs/reports/YYYY-MM-DD-<주제>.md`
- CEO 결정: `docs/decisions/YYYY-MM-DD-<주제>.md` (배경 / 선택지 / 결정 / 근거 / 영향)
- 계획: `docs/plans/YYYY-MM-DD-<주제>.md`

결정 문서는 나중에 뒤집지 않는다. 번복 시 새 파일을 만들고 이전 문서를 링크한다.
