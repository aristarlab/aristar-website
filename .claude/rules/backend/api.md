# API·서버 규칙

- 모든 입력은 핸들러 첫 줄에서 **Zod로 검증**한다. 검증 전 값을 쓰지 않는다.
- 응답 형태는 둘 중 하나로 고정한다: `{ data }` 또는 `{ error: { code, message } }`
- HTTP 상태코드를 정확히 쓴다. 에러를 200으로 감싸지 않는다.
- 에러 메시지에 스택트레이스·내부 경로·쿼리문을 노출하지 않는다. 서버 로그에만 남긴다.

## 시크릿

- 시크릿은 `process.env`에서만 읽는다. 코드·테스트·로그에 리터럴로 쓰지 않는다.
- 필요한 환경변수는 `.env.example`에 **키 이름만** 추가한다.
- 클라이언트로 내려가는 값은 `NEXT_PUBLIC_` 접두어가 붙은 것뿐이다. 시크릿에 이 접두어를 붙이지 않는다.

## 외부 연동

- Gmail API 호출은 `lib/server/gmail/`에만 둔다. 라우트 핸들러에서 직접 호출하지 않는다.
- 외부 호출에는 타임아웃과 재시도 상한을 둔다. 무한 재시도 금지.
- 메일 본문을 DB·로그·저장소에 저장하지 않는다. 분류에 필요한 메타데이터(수신시각, 발신 도메인, 라벨, 사업 슬러그)만 다룬다.

## 문의 폼

문의 폼을 만들 경우: 레이트 리밋 필수, 봇 차단(허니팟 또는 Turnstile), 개인정보 최소 수집(이름·메일·내용), 수집 항목은 `privacy.html`과 일치해야 한다. 불일치는 법무 검토 대상이다.
