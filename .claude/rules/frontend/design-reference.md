# 해외 레퍼런스 UI/UX 적용 규칙

CEO 지시: 웹사이트 재구성 시 **해외 유명 웹사이트의 UI/UX를 참고**한다.
참고는 **패턴 수준**에서만 한다. 복제가 아니다.

## 참고 축과 대상

| 참고 축 | 대표 레퍼런스 | 우리가 가져올 것 |
|---|---|---|
| 제품 쇼케이스 전개 | Apple | 큰 여백·큰 타이포의 전면 타일, 한 화면 한 메시지, 스크롤에 따른 단계적 공개 |
| 제품 구조 설명 | Stripe | 추상 개념을 다이어그램으로 보여주는 섹션, 정밀한 타입 스케일 |
| 담백한 프로덕트 톤 | Linear | 절제된 색 사용 — 액센트는 클릭 가능한 것에만. **"다크 톤 강조 블록"은 전제 오류로 폐기**(Linear 마케팅 사이트는 전체가 다크 캔버스다). 전환 시간 수치는 비공식 역추출이라 쓰지 않는다. `prefers-reduced-motion`·포커스는 Linear가 아니라 WCAG 2.3.3 / 2.4.7을 근거로 쓴다 |
| 정보 밀도와 가독성 | Notion | 명확한 섹션 계층, 읽기 편한 본문 폭(60~80자) |
| 서비스 카드 그리드 | Vercel | 동일 리듬의 카드 그리드, 상태 배지 표기 |

**2026-11-06 갱신**: `index.html`은 더 이상 Apple 계열 쇼케이스 언어를 쓰지 않는다. CEO 결정으로 색인 방향(잉크 스케일 + 고운바탕/IBM Plex Sans KR + 동일 구조 색인 행)으로 교체됐다 — `docs/decisions/2026-11-06-visual-direction-index.md`. 위 표의 패턴은 **참고 축**으로 유지하되, 적용 시 확정된 토큰과 "비트리거 모션 없음" 원칙을 넘지 않는다.

## 적용 기준 (벤치마킹 산출물에 반드시 포함)

1. **패턴 이름** — 무엇을 참고하는가 (예: "전면 타일 + 단계적 공개")
2. **왜 우리에게 맞는가** — 조용한 톤, 3개 사업 구성, 미출시 제품이 있는 상황에 맞는 근거
3. **우리 식 변형** — 확정 토큰(`web.md` 참조: 잉크 스케일 + `--signal #2E6354`, 고운바탕 + IBM Plex Sans KR, 라운드는 상호작용 표면에만)으로 어떻게 구현하는가
4. **버린 것** — 참고 대상의 어떤 요소는 왜 쓰지 않는가

## 반드시 지키는 구현 기준

- 디자인 토큰과 폰트는 `web.md`의 확정 값을 유지한다. 토큰 추가·변경은 브랜드팀 승인 사항이다.
- 한국어 조판을 먼저 검증한다. 영문 기준 타이포 스케일을 그대로 쓰면 한국어가 깨진다. `word-break: keep-all`, 자간(`letter-spacing`)은 한국어에서 과하게 좁히지 않는다.
- **비트리거 모션을 쓰지 않는다**(CEO 확정). 스크롤 전개 효과를 도입하지 않는다. 사용자 동작에 답하는 전환만 두고, 그것도 `prefers-reduced-motion`을 존중한다.
- 성능 예산: 초기 JS 150KB(gzip) 이하, LCP 2.5초 이하. 레퍼런스 흉내를 내려고 무거운 라이브러리를 들이지 않는다.
- 접근성은 레퍼런스보다 우리 규칙(`web.md`)이 우선한다.

## 금지 (저작권·상표)

- 타 사이트의 **카피 문구, 이미지, 아이콘 세트, 일러스트, 폰트 파일, CSS·코드를 복제하거나 거의 그대로 옮기지 않는다.**
- 특정 브랜드를 연상시키는 상표적 요소(로고 형태, 고유 일러스트 스타일, 시그니처 그래픽)를 모방하지 않는다.
- 레퍼런스 사이트의 자산을 다운로드해 저장소에 넣지 않는다.
- 레퍼런스에 있다는 이유로 **우리 제품에 없는 기능**(가격표, 고객 로고, 수치 대시보드, 후기)을 화면에 그려 넣지 않는다. 없는 섹션은 비워두지 말고 제거한다.
